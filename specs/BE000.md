# BE000 - Kế hoạch triển khai backend bản tối thiểu

**Công nghệ:** Node.js, Fastify, TypeScript.
**Thư mục triển khai:** `backend/`.
**Phạm vi:** nhận câu trả lời đầy đủ, chưa streaming, chưa database.

| Thứ tự | Feature                                        | Kết quả cần đạt                                                                                                   |
| ------ | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 1      | Khởi chạy backend và health check              | Server chạy được; `GET /api/health` trả trạng thái hoạt động                                                      |
| 2      | Cấu hình môi trường                            | Đọc base URL, token và timeout từ môi trường; báo rõ khi thiếu cấu hình; có `.env.example` không chứa secret      |
| 3      | Danh sách mô hình                              | `GET /api/models` trả ID, tên và provider của các mô hình được phép dùng                                          |
| 4      | Kiểm tra yêu cầu sinh câu trả lời              | `POST /api/generate` nhận câu hỏi và model ID; từ chối câu hỏi rỗng, dữ liệu sai hoặc mô hình không hợp lệ        |
| 5      | Sinh câu trả lời từ một mô hình                | Backend gọi proxy bằng token và trả nội dung Markdown đầy đủ                                                      |
| 6      | Đo thời gian phản hồi                          | Mỗi kết quả có thời gian tính từ lúc gọi proxy đến khi nhận xong câu trả lời                                      |
| 7      | Xử lý lỗi và timeout                           | Phân biệt dữ liệu sai, lỗi xác thực, vượt hạn mức, lỗi dịch vụ và timeout; trả thông báo phù hợp, không lộ secret |
| 8      | Xử lý nhiều yêu cầu đồng thời và retry độc lập | Hỗ trợ 2–4 yêu cầu song song; một yêu cầu lỗi không ảnh hưởng yêu cầu khác; có thể gửi lại riêng yêu cầu thất bại |
| 9      | Hoàn thiện và bàn giao                         | Kiểm tra luồng thành công/lỗi bằng proxy thật; README hướng dẫn chạy, cấu hình và giới hạn đã biết                |

## Quyết định thiết kế

Mỗi request sinh câu trả lời xử lý một mô hình. Frontend gửi 2–4 request đồng thời tới backend; retry dùng lại endpoint đó, không cần endpoint riêng. Chỉ backend gọi dịch vụ LLM.

## Phụ thuộc

Feature 3 và 5 cần xác minh contract liệt kê/chọn mô hình và có token. Có thể dùng dữ liệu giả để phát triển trong lúc chờ, nhưng chỉ nghiệm thu tích hợp sau khi chạy với proxy thật.

## Ngoài phạm vi

Streaming, Thinking, metrics token/chi phí, lịch sử hội thoại và đăng nhập.
